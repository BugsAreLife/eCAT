# 管控软件 · 展示网页（初稿 v0.3）

析氢催化剂实验平台的**管控软件界面初稿**：深色科技风、顶部导航窗格、**四层逐级下钻**、模拟数据驱动、零依赖。

## 一、怎么打开

**双击 `index.html`**（推荐 Chrome / Edge）。

- 不需要服务器、不需要联网、不需要安装任何依赖
- 全部为本地脚本，`file://` 下可直接运行
- 打开即进入**首页**（第 1 层），从这里逐层点进去

## 二、信息架构（逐层下钻）

```
第 1 层  首页       #/home
第 2 层  运行监控   #/monitor    实验数据 #/data      智能编排 #/ops
第 3 层  驾驶舱     #/monitor/dashboard      实验档案 #/data/archive     任务中心 #/ops/tasks
        数字孪生   #/monitor/twin           轮次详情 ↓ 第 4 层            Agent   #/ops/agent
        告警日志   #/monitor/logs
第 4 层  轮次详情   #/data/archive/R-008（R-001…R-009 任意轮次）
```

**三条等价的下钻路径**（都能回到任意一层）：

1. **顶部一级导航**：首页 / 运行监控 / 实验数据 / 智能编排
2. **二级导航条**：进入模块后出现在下方（模块总览 + 该模块各页面）
3. **右上角面包屑**：`首页 › 实验数据 › 实验档案 › R-008`，每一段可点

页面内还有第四种：卡片点进去（首页模块卡 → 模块页卡 → 表格行）、`← 返回上级` 按钮、轮次详情的「上一轮 / 下一轮」。

## 四、设计要点

**科技感（v0.3 视觉系统）**

1. 深色底 + 双层氛围光（青 / 蓝径向渐变）+ 顶部网格背景，网格用 `mask-image` 向下淡出，不干扰阅读。
2. 卡片统一 HUD 角标（左上/右下 1.5 px 青色折角），标题前有发光竖条。
3. 所有数字用等宽字体 + 青色外发光（`tabular-nums`，跳动时不抖动）。
4. 状态语义色：运行 `#34d399` / 挂起 `#fbbf24` / 停机 `#f87171` / 待机灰；点状指示器带同色辉光。
5. 导航用「一级下划线 + 二级胶囊」两套激活态，面包屑用等宽字体 + `›` 分隔。
6. `prefers-reduced-motion` 下关闭所有 hover 位移与闪烁。

**为什么这么排**：评委前 10 秒只关心「是什么 / 现在活着吗 / 做到什么程度」，所以首页按此顺序；第二层给"先看数字再选页"的缓冲；第三层是干活的地方；第四层才给单轮全部证据——避免一上来就把表格和曲线糊一脸。

## 五、文件结构

```
展示网页/
├── index.html            应用外壳
├── app.js                入口：导航/路由/顶栏/循环
├── 产品制作方案.md        制作方案（PLAN-SW-001）
├── README.md             本文件
├── assets/
│   ├── app.css           设计系统
│   └── data.js           模拟数据集（固定种子，可复现）
├── core/
│   ├── bus.js            全局状态 + 事件总线
│   └── sim.js            模拟数据源 + 实验状态机（MockSource）
├── ui/kit.js             组件 + 自绘图表（折线/散点/甘特/DAG/迷你图）+ 页面头
├── _截图/                 验收截图（首页/模块/驾驶舱/档案/轮次详情/孪生…）
└── views/
    ├── home.js            第 1 层：首页（总览 + 实时状态软刷新）
    ├── module.js          第 2 层：模块总览（三个模块共用，含层级示意条）
    ├── dashboard.js       第 3 层：驾驶舱
    ├── twin.js            第 3 层：数字孪生（3D 占位）
    ├── archive.js         第 3 层：实验档案（点行下钻）
    ├── round.js           第 4 层：轮次详情
    ├── tasks.js           第 3 层：任务中心
    ├── agent.js           第 3 层：Agent 工作台
    └── logs.js            第 3 层：告警与日志
```

> **加一个页面**：写 `views/xxx.js` 注册 `A.views.xxx` → 在 `core/bus.js` 的 `A.pages` 加元数据、把 key 塞进某个 `A.groups[].pages` → 在 `index.html` 加 `<script>`，并在 `app.js` 的路由解析里无需改动（`#/模块/页面` 自动可用）。
> **加一个模块**：在 `A.groups` 追加一项（含 `key/name/ic/sub/desc/pages`），首页 `MODS` 与 `A.allRoutes` 同步。

## 六、3D 模型怎么接入（下一步）

1. 把 `平台改造/3D数字孪生/` 下的 `engine3d.js`、`scene.js` 复制到本目录
2. 在 `index.html` 里加 `<script src="engine3d.js"></script>`、`<script src="scene.js"></script>`
3. 把 `views/twin.js` 里的 `drawPlaceholder()` 调用换成 3D 引擎渲染（画布容器 `.twin-canvas` 已是深色底，可直接用）
4. 着色沿用 `A.sim.partStateOf(name)`（命名与规格书一致：`M-PUMP-01`…`R-07`）

## 七、改内容在哪里改

| 想改什么 | 改哪里 |
|---|---|
| 导航层级 / 模块划分 | `core/bus.js` 顶部 `A.pages`、`A.groups` |
| 路由跳转 | 任意元素加 `data-go="模块/页面/参数"`（app.js 全局代理） |
| 轮次/配方/指标数据 | `assets/data.js`（ROUNDS 生成逻辑） |
| 工序名称与时长 | `assets/data.js` 顶部 `STEPS` |
| 故障类型与话术 | `core/sim.js` 顶部 `FAULTS` |
| Agent 应答话术 | `views/agent.js` 的 `reply()` |
| 颜色/字号/间距/发光 | `assets/app.css` 的 `:root` 变量 |
| 页面文案 | 对应 `views/*.js` |

## 八、已知限制

1. **全部数据为模拟**：界面右上角固定标注「演示数据 · 模拟运行」。
2. **自然语言下单是规则解析**（正则抽取），不是大模型推理。
3. **Agent 对话为脚本化应答**，不接真实 LLM。
4. **3D 为占位线框**，非 CAD 模型。
5. 未做登录/权限/移动端/真实设备接入（见《产品制作方案》§1.3 不做清单）。
6. 深色主题下若投影仪亮度偏低，建议现场把系统亮度拉满（对比度已按 WCAG AA 调过正文）。
